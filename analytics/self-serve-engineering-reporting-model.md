# Self-Serve Engineering Reporting Model

## Background

Teams often depend on analysts to answer recurring questions because source data is hard to access, interpret, or use consistently.

## Problem

Stakeholders needed reporting that was self-serve enough to reduce reliance on manual support, while still being robust enough to trust for operational decisions.

## What I built

I helped create a structured reporting model that combined multiple inputs into a clearer, more reusable analytics layer. This enabled stakeholders to answer more questions independently through curated reporting outputs.

## Tools used

- SQL
- Power BI
- DAX
- Power Query
- Excel

## Users / scale

- Used by engineering, finance, and programme stakeholders
- Supported recurring reporting and decision-support needs
- Designed to reduce dependency on manual analytical support

## Outcome

- Improved access to self-serve analysis
- Reduced repeated manual investigation
- Increased consistency in how reporting outputs were used and interpreted

## What I learned

Self-serve reporting only works when the underlying logic is structured and trusted. Good semantic design reduces both analyst workload and stakeholder confusion.

## What I would improve

I would add more reusable documentation, clearer definitions within reporting outputs, and a stronger feedback loop for evolving stakeholder needs.
