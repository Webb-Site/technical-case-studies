# Feature Family Analytics

## Background

Complexity can be difficult to discuss usefully when analysis stays at too high a level. Stakeholders needed reporting that grouped information into more meaningful analytical structures.

## Problem

Without clearer groupings, it was harder to understand how related features or parts were contributing to overall complexity and where the most meaningful intervention opportunities might sit.

## What I built

I developed analytical logic and reporting around grouped feature and part-family structures to make complexity drivers easier to interpret. This made reporting more useful for structured decision-making and investigation.

## Tools used

- SQL
- Power BI
- DAX
- Power Query
- Excel

## Users / scale

- Used within complexity and decision-support analysis
- Supported structured investigation of related feature and part groups
- Designed to improve interpretability of reporting outputs

## Outcome

- Made reporting more meaningful by grouping related drivers
- Supported more targeted investigation of complexity contributors
- Improved the usability of analysis for stakeholder discussions

## What I learned

Analytical structure matters. Grouping logic can be just as valuable as visualisation when it makes reporting easier to interpret and act on.

## What I would improve

I would add more flexible grouping logic, stronger documentation of definitions, and clearer comparison views across related families.
