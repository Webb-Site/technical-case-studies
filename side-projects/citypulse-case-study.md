# CityPulse Case Study

## Background

Transport reliability and disruption analytics are strong examples of where data engineering and analytics can support better operational understanding.

## Problem

I wanted to build a project that explored how live transit data could be ingested, modelled, and turned into useful metrics and scenario outputs in a more modern data-stack style workflow.

## What I built

I built a cloud-based transit analytics project that ingested live feeds, stored them in cloud data services, modelled them through staged transformations, and published metrics and scenario-oriented outputs for reliability and disruption analysis.

## Tools used

- Python
- SQL
- BigQuery
- Google Cloud Storage
- dbt
- Data modelling
- Data quality / testing
- GitHub Actions or scheduled orchestration

## Users / scale

- Built as a side project / portfolio project
- Designed to reflect modern data workflow concepts
- Focused on transport and reliability analytics

## Outcome

- Produced a portfolio project aligned to transport, analytics, and data-platform interests
- Strengthened my understanding of staged modelling, cloud-based workflows, and data quality concepts
- Created a clearer bridge between analytics and production-minded data delivery

## What I learned

This project helped me think more clearly about the full path from ingestion to modelling to serving metrics. It also showed how useful a small but well-structured project can be for demonstrating technical direction.

## What I would improve

I would expand the source coverage, add richer scenario outputs, and improve monitoring and deployment around the pipeline.
